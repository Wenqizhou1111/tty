# 代龙 —— Windows 10 / 11 输入法

安装包叫 `tty.exe`，产品名是**代龙**。

Windows 10 / 11 上可以真正装起来用的中文 + 英文输入法。
C# / .NET Framework 4.8，独立进程 + 全局键盘钩子，**不需要 Visual Studio、不需要 .NET SDK**
就能从源码构建（用系统自带的 `csc.exe`）。

主打三件事：**打字够用**、**打游戏不打扰**、**AI 帮你改文字**。

---

## 一、功能一览

| 你的需求 | 实现情况 |
| --- | --- |
| 本地汉字联想词库扩充到常用 4000 字 | **5286 个不同汉字**，覆盖 **407 个普通话音节**，每个音节内的字按常用度排序 |
| 常用 1000 条本地联想词库 | **1829 条词组**（自动生成 1220 + 人工精选 609），上屏后按末字自动联想 |
| 一个按键锁定输入法，打游戏不卡出输入法 | **Ctrl+Alt+L** 一键锁定。锁定时键盘钩子被**整体卸载**，所有按键原样传给游戏，输入法完全不介入 |
| 加入英文输入法 | 中英一键切换（轻按 Shift 或 Ctrl+Alt+E）+ **4000 个英文常用词**的本地补全 |
| 一个 AI 接口可以接入各种 API | **15 个服务商预设** + Anthropic 协议 + 完全自定义的请求体模板；支持 SSE 流式输出 |
| 纠错 / 辅助生成语句 | 润色、扩写、续写、纠错、翻译、摘要、正式化、口语化 八种动作 |
| 使用时在输入条弹出输入口向 AI 提要求 | AI 面板：一个独立的悬浮窗口，可以选风格，也可以直接写要求 |
| 两种模式 | **自动读取修改**（选润色效果，自动读当前输入框） / **指令模式**（写要求，对框内文字润色·扩写·续写） |
| 界面参考微信输入法 | 悬浮候选条（圆角、微信绿、无边框、不抢焦点）+ 微信风格的设置界面 |

另外还实现了不少计划外但用得上的东西：

- **模糊音**：zh/z、ch/c、sh/s、n/l、an/ang、in/ing、uan/uang 可分别开关
- **简拼**：`nh` 出「你好」
- **用户词库**：你上屏过的词会自动学习并往前排
- **中文标点**：逗号句号问号自动转全角，引号成对翻转
- **多屏 / 高 DPI**：候选条跟着光标走，不会跑到屏幕外
- **深浅色主题**：跟随系统
- **完整日志**：出问题把日志发过来就能定位

## 二、三步上手

### 1. 安装

双击 `dist\tty\tty.exe`，一路下一步。（安装包文件名就是 `tty.exe`）

- **默认装到当前用户目录，不需要管理员权限**（LOCALAPPDATA 下的 Programs 目录）
- 想给所有用户装，就用管理员身份运行，它会自动改成装到 Program Files
- 安装完托盘会出现一个绿色「墨」字图标

静默安装（批量部署用）：

~~~powershell
.\tty.exe --silent-install
.\tty.exe --silent-install --dir "D:\Tools\MyIME"
.\tty.exe --silent-uninstall
~~~

> **可选步骤失败不会让安装报失败。**
> 「写入卸载信息 / 创建快捷方式 / 开机自启 / 记录安装位置 / 装完启动」这几步如果被
> 组策略或权限挡住，安装会**照常成功**（退出码 0），并把失败原因写成中文警告打到
> stdout 和日志里。只有**复制程序文件**失败才会真的返回 1 —— 否则程序明明装好了却报失败，
> 用户会去卸载重来，白折腾。

### 2. 打开任意输入框开始打字

在记事本、浏览器、微信里敲 `nihao`，光标下方会浮出候选条，按空格上屏「你好」。

不需要用 Win+Space 切换 Windows 输入法，它就是一个常驻的键盘钩子。

### 3. 改设置

托盘图标右键 → 设置，或者按 `Ctrl+Alt+S`。

## 四、游戏锁定（重点）

### 它到底做了什么

按下锁定的瞬间，输入法会**把自己的键盘钩子整个卸载掉**。

不是「钩子里判断一下然后放行」，而是**钩子根本不存在**。这意味着：

- 游戏收到的按键和没装输入法时**完全一样**，一个都不少、一个都不变
- 不可能弹出候选条
- 反作弊软件扫不到任何额外的键盘钩子
- 输入法进程本身还在（托盘图标还在），只是完全不碰键盘了

再按一次同一个热键就解锁。

### 自动锁定

设置里可以打开两个开关，让它自己判断：

- **检测到全屏游戏时自动锁定** —— 前台窗口盖满整个显示器，或者系统报告正在跑 D3D 独占全屏
- **检测到常见游戏进程时自动锁定** —— 内置了一份常见游戏名单（英雄联盟、CS2、原神、星穹铁道、绝地求生、艾尔登法环等），也可以自己加

命中就自动锁，退出游戏自动解。

### 建议

锁定热键**别设成游戏里会用到的键**。默认的 `Ctrl+Alt+L` 在绝大多数游戏里都没占用。
如果你玩的游戏刚好用到了，改一个就是（设置 → 快捷键）。

## 五、AI 写作助手

### 怎么开启

1. 设置 → **AI 写作** → 打开「启用 AI 写作助手」
2. 选服务商（下拉框里已经内置了常见的一堆），把 API Key 填进去
3. 保存。正在运行的输入法会**立刻**读到新配置，不用重启

### 两个模式

**模式一 · 自动读取修改**

按 `Ctrl+Alt+P`。输入法会先读你当前输入框里的文字（UI Automation 优先，
读不到就走剪贴板），然后弹出面板。面板上是一排**润色效果**：

简洁 / 正式 / 口语 / 专业 / 亲切 / 书面 / 强力纠正 / 提炼要点

点一个，AI 就开始改，结果一边生成一边显示。满意就点「替换原文」。

**模式二 · 指令输入改写**

按 `Ctrl+Alt+A`。面板上有一个输入框，你直接写要求，比如：

- 「改得更正式一点」
- 「把这段话缩短一半」
- 「再往下写两句」
- 「改成给客户看的语气」

再选一个**动作**：润色 / 扩写 / 续写 / 纠错 / 翻译 / 摘要 / 正式化 / 口语化。
点「开始处理」，AI 就按你的要求处理框里的原文。

### 结果怎么用

| 按钮 | 行为 |
| --- | --- |
| 替换原文 | 全选原输入框内容，用 AI 结果覆盖。**替换前会核对选中的内容和你当初编辑的是不是同一段**，不一致就中止；**选中超过 5000 字也一律拒绝**，避免误删整篇 |
| 插入 | 只在光标处插入结果，不动原文 |
| 复制 | 复制到剪贴板 |
| 重试 | 用同样的参数再请求一次 |

### 支持哪些 API

内置预设（选一个就自动填好地址和模型）：

OpenAI、DeepSeek、月之暗面 Kimi、智谱 GLM、通义千问、百度文心千帆、火山方舟（豆包）、
MiniMax、零一万物、阶跃星辰、腾讯混元、硅基流动、Ollama（本地）、LM Studio（本地）、
Anthropic Claude，以及**自定义**。

绝大多数服务商走的是 OpenAI 兼容协议，Anthropic 走自己的协议。

**自定义**那一项可以对接任何形状的接口：自己填 API 地址、请求头，请求体可以写模板占位符：

~~~
{"model": {{model}}, "messages": [{"role":"user","content": {{user}}}], "stream": {{stream}}}
~~~

可用占位符：`{{model}}` `{{system}}` `{{user}}` `{{temperature}}` `{{max_tokens}}` `{{stream}}`。
字符串类占位符会连引号一起替换，值本身做好 JSON 转义。

返回结果如果结构很怪，可以在「响应字段路径」里写 `data.choices[0].message.content` 这种路径直接指到正文。

**API Key 用 Windows DPAPI 按当前用户加密后存储**，设置文件里不会出现明文，换台机器也解不开。

## 六、从源码构建

### 你需要什么

- Windows 10 或 11
- .NET Framework 4.8（Win10 1903 以后和 Win11 都自带）
- 没了

**不需要** Visual Studio，**不需要** Windows SDK，**不需要** .NET SDK。

### 构建

~~~powershell
.\build.ps1              # 构建全部产物到 out 目录

## 八、词库怎么改

### 加词（最简单）

直接编辑 data 目录下的 words_extra.txt，一行一个词：

~~~
shu ru fa 输入法 9600
gao de di tu 高德地图 8200
~~~

- 拼音音节用**单个空格**分隔，**不带声调**
- ü 一律写成 `v`：女就是 `nv`，绿就是 `lv`，旅行就是 `lv xing`
- 最后是权重，越大越靠前（1000 到 9999）
- 拼音音节数必须等于词的汉字数

改完重新跑一次 `.\build.ps1` 让文件复制到 out 下的 data 目录，
或者直接改安装目录里 data 下的 words_extra.txt 再重启输入法。

### 加字

编辑 data 目录下的 chars.txt，一行一个音节：

~~~
ni 你 尼 泥 呢 逆 妮 腻
~~~

**顺序就是候选顺序**，最常用的放最前面。

### 你打过的词

输入法会把你上屏过的词自动记到用户词库里，路径在设置 → 词库 页面能看到，
也可以手工编辑。想清空就在那个页面点「清空用户词库」。

### 换一套码表

引擎不认「拼音」这个概念，它只认「键序列到词」的映射。理论上换成双拼、五笔只要换掉
chars.txt 和 words.txt 里的码、再改 syllables.txt 就行。
不过切分逻辑本身是按拼音音节写的，换成非拼音方案需要改 PinyinEngine.SegmentPlain。

### 开发中被测试抓出来并修掉的真实 bug

1. **「短词 + 尾巴补全」的候选把消耗音节数记成了 k 而不是全部**，
   结果 `zhongguo` 上屏「中国」之后缓冲区里还残留 `guo`，
   接着打 `shurufa` 就串成了「国书如发」。
2. **「首音节候选字 + 尾巴补齐」同样把自己标成只消耗 1 个音节**，同一类问题。
3. **简拼在输入中途不算「还能继续敲」**，`nh` 会被当成非拼音直接上屏成字面量 nh。
4. **输入条每次刷新都新建 4 个 Font 对象**。这在键盘钩子回调里是危险操作，
   一旦拖过 Windows 的 LowLevelHooksTimeout（默认 300ms），钩子会被系统直接摘掉 ——
   表现就是「输入法突然失灵」。已改成缓存字体。
5. **设置界面一启动就 NullReferenceException**：`BuildChrome()` 里每调一次
   `Controls.Add()` 都会立刻触发 `OnLayout`，而那时后面的控件字段还没赋值。
6. **单音节输入的首选字被词表带偏**。词表里顺带收的单字（鸡、事、鱼…）拿了整词的加成，
   于是 `ji` 首选「鸡」而不是「几」、`shi` 里「事」压过「时」、`yu` 首选「鱼」而不是「于」。
   已改成单音节输入时单字排序**一律以 chars.txt 为准**（那张表本来就是逐音节按常用度排的）。
   单音节输入是最高频的操作，这处错位体感很明显。

前五条只有真跑起来才会暴露；第六条是靠命令行诊断发现的：

~~~
.\out\EngineTests.exe --rank          看一批高频音节的候选排序
.\out\EngineTests.exe --rank ji,shi   只看指定音节
~~~

把它和 chars.txt 的顺序对照一眼，就能看出排序有没有被带偏。

### 没能在这台机器上实测的（环境限制，不是代码问题）

- **注册表写入**：开发沙箱拒绝一切 HKCU / HKLM 写入。所以「卸载信息」和「开机自启」
  只验证了代码路径不抛异常，**没有**验证注册表里真的写进去了值。
- **快捷方式创建**：开始菜单和桌面都不在沙箱可写范围内。
- **真实 AI 接口调用**：开发时没有可用的 API Key。AI 层只做了本地假服务器测试
  （135 项，覆盖 SSE 流式、三种协议、自定义模板、401/404/429/5xx/超时的中文提示、
  以及 API Key 不会泄漏到错误信息里）。
- **真机上手动打字、游戏里锁定、非美式键盘布局下的标点映射**。

上面这几项请你在真实环境里过一遍。

## 十、已知限制

老实说清楚，免得踩坑：

1. **提权窗口打不进去**。因为输入法是以普通权限运行的独立进程，往「以管理员身份运行」的程序里
   注入文字会被 Windows 的 UIPI 拦掉。解决办法：让输入法也以管理员身份运行。
2. **它不是 TSF 输入法**。它不走 Windows 的 Text Services Framework，而是常驻进程 + 全局键盘钩子。
   好处是免管理员、能构建、玩游戏时更稳；代价是**没有行内组合下划线**
   （拼音显示在悬浮条上，而不是文档里），以及少数特殊程序（部分 UWP、部分游戏内聊天）可能打不进去。
3. **中文标点按美式键盘布局映射**。如果你用的是非美式布局，个别标点可能映射错，
   可以在设置里关掉「中文标点」。
4. **联想是末字联想**，不是整句语言模型。它按你上屏的最后一个字去词库里找常用词。
   真正的整句预测交给 AI 面板。
5. **AI 替换是全选后覆盖**。如果你的输入框里混着不想动的内容，请用「插入」而不是「替换」。
   为了防呆，这里加了两道闸：**自动读取超过 5000 字就判定"读到的不是输入框"直接忽略**
   （读取链在拿不到输入框时会退到"读整个文档"，那样拿去替换会闯大祸），
   **选中内容超过 5000 字也一律拒绝替换**，并提示改用「插入」。
6. **内置游戏名单不可能覆盖所有游戏**。建议同时打开「全屏自动锁定」，那个是通用判断。

## 十一、关于仓库里那份 C++ TSF 骨架

legacy-tsf-cpp 目录里是项目最初的一份 **C++ / TSF 输入法骨架**
（TextService.cpp、Register.cpp、CMakeLists.txt 那一套），
配一份 6 万字的《设计文档.md》，讲透了 TSF 的生命周期、注册表结构、15 条坑清单。

它**没有被删掉**，因为那份文档本身很有价值：如果你以后想做正经的 TSF 输入法，
里面的东西能省掉大量试错。

但当前交付的输入法**不是**基于它 —— 因为开发这台机器上没有任何 C++ 编译器和 Windows SDK，
那份骨架编译不了、验证不了、也打不出安装包。所以换成了你现在看到的 C# 实现。

## 十二、出问题了怎么办

1. **先看日志**：托盘右键 → 「打开日志文件夹」，日志在 APPDATA 下 MyIME 的 logs 目录里。
2. 常见情况：
   - **打字没反应** → 可能锁定了，按一下 `Ctrl+Alt+L`；
     或者热键被别的软件占了（日志里会写「热键注册失败」）
   - **候选条不出现** → 看日志里有没有「安装键盘钩子失败」
   - **AI 报错** → 面板底部会显示中文原因（Key 无效 / 地址不对 / 超时 / 额度用尽）
   - **打游戏弹候选框** → 打开设置里的「检测到全屏游戏时自动锁定」
3. 日志里**不会**出现明文 API Key（做了打码处理）。

## 十三、开发者备注：为什么源码里看不到 C# 6 的语法

因为构建用的是 Windows 自带的 `csc.exe`，它是 **C# 5** 编译器。
所以整个代码库刻意避开了字符串内插、空传播运算符、nameof、表达式体成员、
自动属性初始化器等新语法，全部用 public 字段 + 字段初始化器。

这样做的代价是代码啰嗦一点，换来的是：**任何一台 Windows 10/11 都能直接构建，不用装任何东西。**
